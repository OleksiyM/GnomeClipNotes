# Product direction

GnomeClipNotes turns captured text into material worth keeping and working with.

The name describes that movement:

- **GNOME** — the desktop environment and native interaction conventions.
- **Clip** — the clipboard as a source and a tool for collecting fragments.
- **Notes** — the deliberate, retained result rather than an endless capture log.

**Capture → Curate → Organize → Export → Develop → Reuse**

Capture starts the process; it is not the whole product. History holds automatic,
temporary captures. Notes and user-created folders hold material the user has
chosen to retain. Human-readable Markdown export lets collected fragments become
a coherent document, then continue into other tools and future work.

Develop means developing ideas and documents, not an integrated programming
environment. Reuse describes what the material enables; it does not promise
unimplemented import, synchronization or round-trip features. The complete
workflow can extend beyond GnomeClipNotes.

## Principles

- Native, readable GNOME interaction, not a custom skin for every control.
- User ownership: local storage, plain text/Markdown and useful export.
- Automatic capture and deliberate retention have different lifetimes.
- Preserve drafts and explain destructive operations before performing them.
- Keep unsupported features and compatibility limits explicit.
- Remain useful as a clipboard tool without requiring a knowledge-management
  methodology or an elaborate organizational setup.

This direction describes the workflow, not a promise of additional in-app features.
